# Reglas de trabajo

- Antes de cada tarea, lee `ai-workspace/01-specs`.
- Si cambia algo, primero se actualiza la spec y su registro de cambios, y después el código.
- Si algo es ambiguo o no está en la spec, para y pregunta.
- En el dominio, TDD: el test va primero, a partir de los escenarios Gherkin.
- Archivos pequeños, con una sola responsabilidad y nombres en inglés.
- Commits pequeños con Conventional Commits.
